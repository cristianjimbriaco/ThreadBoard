# Conclusiones

**Estado:** documento evolutivo.

## Conclusión hasta el Sprint 1

ThreadBoard pasó de una idea y un modelo preliminar a una base de software verificable. El backend ya representa y persiste el dominio central, mientras que el frontend demuestra que la interacción visual propuesta es técnicamente viable mediante React Flow.

La principal limitación actual es que ambas capas todavía no forman un flujo completo para el usuario. Esa separación no invalida el cierre del Sprint 1, porque fue registrada explícitamente y se convirtió en el objetivo principal del Sprint 2.

El proyecto dispone ahora de mejores condiciones para continuar: stack consolidado, ramas ordenadas, build verificado, pruebas, colección Postman, decisiones documentadas y una estructura que permitirá registrar el desarrollo sin reconstruir la historia al final.

## Conclusión final del MVP

Pendiente de completar después del despliegue y la evaluación con usuarios reales.
